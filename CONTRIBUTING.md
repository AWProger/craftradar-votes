# Участие в разработке

Спасибо за интерес! Коротко о правилах.

## Перед началом

* Баг — issue с версиями (плагин, сервер, Java, NuVotifier) и шагами. Без секретов и `config.yml` с `secret`.
* Уязвимость — **не** issue, см. [SECURITY.md](SECURITY.md).
* Крупное изменение (новая функция, смена протокола) — сначала обсудите в issue.

## Разработка

```bash
./gradlew build      # компиляция, тесты, проверка JAR
```

Подробности — [BUILDING.md](BUILDING.md).

* Код и комментарии — в стиле соседних файлов; логика без Bukkit — в `core`, клей Bukkit/Votifier — в `bukkit`.
* Любое изменение поведения — с тестом. Для протокола — обновите [docs/PROTOCOL.md](docs/PROTOCOL.md) и, если затронута подпись, `docs/protocol-vectors.json` (векторы считает PHP `hash_hmac`; тот же файл проверяет сайт).
* Не добавляйте новые runtime-зависимости в JAR без обсуждения (влияет на лицензию и размер).
* Не коммитьте `build/`, `.gradle/`, JAR-файлы (кроме `gradle/wrapper/gradle-wrapper.jar`), серверы/JDK для ручных тестов.

## Pull request

1. Ветка от `main`, один PR — одна задача.
2. CI зелёный (`./gradlew build`).
3. В описании: что и зачем, как проверено, затронут ли протокол.

Отправляя PR, вы соглашаетесь, что вклад распространяется под лицензией репозитория (файл `LICENSE`).
