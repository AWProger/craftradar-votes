# Известные ограничения

| # | Ограничение | Почему | Что остаётся / fallback |
|---|---|---|---|
| 1 | Minecraft 1.6.x — `NOT_TESTED` на реальном сервере | Официальных сборок CraftBukkit 1.6.4 нет (DMCA 2014); BuildTools их не собирает; распространять jar с кодом Mojang мы не можем | Проверено без сервера: компиляция против Bukkit API 1.6.4-R2.0, `ApiLinkCheck` (0 недостающих ссылок), загрузка и инициализация всех 277 классов плагина на Java 8 с `-Xverify:all`. Нужно владельцу: свой законный 1.6.4-сервер на **Java 8** + classic Votifier 1.9 → `realserver/run_scenario.py` |
| 2 | Java 6/7 не поддерживается | Bytecode Java 8 (лямбды, java.time); JDK 21 не умеет `--release 7` | Серверы 1.6/1.7 должны работать на Java 8 (1.7.10 проверен на Java 8) |
| 3 | classic Votifier 1.9: только протокол v1 | v1 не несёт additionalData | Нет `correlation_id` (подтверждение доставки ищется сайтом по нику+timestamp), диагностика распознаётся по service, но подтверждение не отправляется |
| 4 | Деньги (Vault) на реальном сервере не проверены | Vault нет в стабильном репозитории; real-server без экономики | Unit-тесты моста; Vault < 1.4 (String-методы) — fallback рефлексией; на Spigot/старом Paper деньги — только онлайн-игроку (нет `getOfflinePlayerIfCached`), а награды и так выдаются онлайн |
| 5 | Награды игроку на 1.7.10, 26.2 и 26.3 не проверены | mineflayer 4.39 не знает эти протоколы | Мост, очередь, дедуп, конфиг проверены; выдача — тот же код, что проверен на 1.8.8 … 26.1.2 |
| 6 | Spigot/CraftBukkit (не Paper) — `NOT_TESTED` | BuildTools не автоматизирован в стенде | API тот же (compile-matrix по spigot-api 1.8.8 … 26.3 зелёный) |
| 7 | 1.7.10 / 1.8.8: старый Paper предупреждает о «устаревшей сборке» | свойство самих серверов | на работу плагина не влияет |
| 8 | Предметы до 1.13 — только имена материалов этой версии (`DIAMOND` есть везде; `OAK_LOG` на 1.12 — ошибка конфигурации) | flattening 1.13 | валидатор сообщает путь и имя; конфиг между поколениями переносится без потерь, но имена предметов надо подобрать под версию |
| 9 | Нечисловой `timestamp` от мониторинга → 400 и `rejected/` | так требует сайт (PROTOCOL.md §9) | `/crvotes requeue` после исправления на стороне мониторинга |
