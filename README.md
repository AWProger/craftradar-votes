# CraftRadar Votes — голоса CraftRadar и награды за них

Один jar для Bukkit/Spigot/Paper от 1.7.10 до 26.x, Java 8+ (статусы по версиям — [docs/compatibility/minecraft-matrix.md](docs/compatibility/minecraft-matrix.md)). Плагин самодостаточен: **NuVotifier, порты и RSA-ключи не нужны**.

**Простой путь: скачал → вставил ключ → настроил награды.**

1. В кабинете CraftRadar → «Голосования» сервера выберите способ **«Наш плагин»** и нажмите «Выдать ключ» (секрет показывается один раз).
2. Скачайте jar на https://craftradar.ru/votifier.php, положите в `plugins/`, перезапустите сервер.
3. Впишите `key_id` и `secret` в `plugins/CraftRadarVotes/config.yml`, включите `rewards.enabled: true` и настройте награды (генератор YAML — в кабинете), затем `/crvotes reload`.
4. В кабинете нажмите «Проверить подключение»; на сервере — `/crvotes status`.

Как это работает: плагин раз в 5 секунд сам забирает новые голоса CraftRadar по HTTPS (исходящее соединение, подпись HMAC), выдаёт награды и подтверждает обработанные голоса ([docs/PROTOCOL.md](docs/PROTOCOL.md) §10). Пока сервер выключен, голоса ждут на CraftRadar до 7 дней. Повтор голоса не награждается дважды (дедуп по id голоса).

**Если NuVotifier уже стоит**, плагин с ним уживается: порт не занимает, `VotifierEvent` не отменяет и не меняет, только читает. Голоса других мониторингов (TopCraft, MinecraftRating…) он пересылает в статистику CraftRadar, а награждает их по `rewards.handle_votifier_votes` (по умолчанию `auto`: не награждает, если стоит VotingPlugin/SuperbVote/GAListener/VoteRoulette — их награды выдаёт тот плагин). Голоса CraftRadar в способе «Наш плагин» через Votifier не приходят вообще — двойных наград нет, канал выбирает сайт.

**Без нашего плагина** тоже можно: в кабинете способ «Без нашего плагина» — CraftRadar шлёт обычный пакет Votifier на ваш NuVotifier, награды выдаёт ваш плагин наград. Тогда этот jar не нужен (или нужен только для статистики других мониторингов).

Для других плагинов есть событие `ru.craftradar.votes.api.CraftRadarVoteEvent` (главный поток, до встроенных наград; отмена — без встроенной награды): ник, сервис, адрес, время, id голоса и источник (`CRAFTRADAR` / `VOTIFIER`).

Руководство для владельцев — https://craftradar.ru/votifier.php. Протокол: [docs/PROTOCOL.md](docs/PROTOCOL.md), контракт наград: [docs/REWARDS.md](docs/REWARDS.md).

## Схема потоков

```
Способ «Наш плагин»:
  игрок голосует на CraftRadar ─► очередь сервера на CraftRadar (до 7 дней)
        ▲ POST /api/vote_pull.php раз в 5 с (ack обработанных, HMAC)
  CraftRadar Votes ─► CraftRadarVoteEvent ─► встроенные награды (rewards:)

Голоса других мониторингов (если стоит NuVotifier, необязательно):
  мониторинг X ─► NuVotifier ─► VotifierEvent ─► ваш плагин наград (как раньше)
                                    │ (только чтение)
                                    ▼
                          CraftRadar Votes ─► queue/ на диске ─► POST /api/vote_ingest.php (статистика)
                                    └─► награды, если rewards.handle_votifier_votes разрешает
```

## Установка

1. Положите `craftradar-votes-<версия>.jar` в `plugins/` и перезапустите сервер. Появится `plugins/CraftRadarVotes/config.yml`.
2. В кабинете CraftRadar (страница «Голосования» сервера) выберите способ «Наш плагин» и выдайте ключ. **Секрет показывается один раз** — сохраните его.
3. Впишите `key_id` и `secret` в `config.yml`, затем `/crvotes reload`. NuVotifier ставить не нужно.

## Конфигурация (`config.yml`)

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `true` | Связь с CraftRadar |
| `api_url` | `https://craftradar.ru` | Базовый адрес сайта. Если случайно указан полный адрес с `/api/vote_ingest.php`, хвост убирается с предупреждением |
| `key_id` | пусто | Ключ из кабинета; допустимы `A-Z a-z 0-9 _ -`, длина 4–24 (сайт выдаёт `crk_` + 16 hex) |
| `secret` | пусто | Секрет ключа (в логи и команды не попадает) |
| `pull.enabled` | `true` | Забирать голоса CraftRadar с сайта (способ «Наш плагин») |
| `pull.interval_sec` | `5` | Интервал опроса, 2..60 с; сайт может попросить реже (`poll_after`) |
| `allow_insecure_http` | `false` | Разрешить `http://` (только для тестов) |
| `max_queue_size` | `5000` | Предел очереди статистики на диске |
| `log_level` | `info` | `debug` / `info` / `warn` / `error` |
| `rewards.handle_votifier_votes` | `auto` | Награждать ли голоса из NuVotifier: `auto` — да, если нет стороннего плагина наград; `true` — всегда; `false` — никогда |

При пустых `key_id`/`secret` или неверном `api_url` в консоль выводятся понятные ошибки по-русски, связь с CraftRadar выключена до исправления и `/crvotes reload`.

## Команды

`/crvotes status|flush|reload|requeue [all|<id>]|rewards <status|test <ник> [dry]|reload>`, право `craftradar.votes.admin` (по умолчанию op).

* `status` — способ в кабинете, когда был последний опрос CraftRadar, сколько голосов получено и ждут подтверждения, найден ли NuVotifier и награждаются ли его голоса, награды вкл/выкл, очередь статистики и `rejected/` (предел 1000), последние ошибки;
* `flush` — опросить CraftRadar и отправить очередь статистики сейчас (сбросить паузы повторов);
* `reload` — перечитать `config.yml` (старые потоки останавливаются, до 5 с ожидания);
* `requeue [all|<id>]` — вернуть события из `rejected/` в очередь с обнулёнными попытками (без аргумента — все). `<id>` — имя файла без `.json`.

* `rewards status` — состояние наград: включены ли, ошибки конфигурации, очередь, неопределённые действия;
* `rewards test <ник> [dry]` — выдать награду онлайн-игроку, не трогая дедуп, серии и лимиты; `dry` только пишет в журнал;
* `rewards reload` — перечитать `config.yml` и перезапустить только награды.

## Награды за голоса

Локальный движок наград: блок `rewards:` в `config.yml`, **по умолчанию `enabled: false`**. Сайт команд на сервер не отправляет, всё настраивается и выполняется только здесь. Контракт: [docs/REWARDS.md](docs/REWARDS.md).

* **Где взять YAML.** Генератор на странице голосований в кабинете собирает блок целиком; вставьте его в `plugins/CraftRadarVotes/config.yml` вместо `rewards:` и выполните `/crvotes rewards reload`. Описание всех ключей (`services`, `timezone`, `daily-limit`, `default`, `weighted-pool`, `streaks`, `offline-queue`, `duplicate-protection`, `dry-run`, `logging`) — комментарии в `config.yml`. Плейсхолдеры: `{player}` (команды, `message`, `broadcast`) и `{service}` — имя мониторинга (только `message`/`broadcast`; небезопасные символы заменяются на «мониторинг»). Деньги — через Vault, если он установлен; шансы — `weighted-pool`; серии — `streaks`; лимит — `daily-limit`; оффлайн-игроки — `offline-queue`.
* **Обновление.** Новый jar не перезаписывает ваш `config.yml`: блок `rewards:` из свежего конфига добавьте вручную.
* **Невалидный конфиг** (неизвестный ключ, другой `{...}`, значение вне диапазона): `rewards` не запускается (`CONFIG_INVALID`), ошибки с путём видны в консоли и в `/crvotes rewards status`; пересылка голосов работает; при `reload` остаётся прежний валидный набор.
* **Журнал** `plugins/CraftRadarVotes/rewards.log`, состояние `rewards-state.json` (дедуп, серии, суточные счётчики, очередь). Статусы: `VOTE_RECEIVED`, `REJECTED_DUPLICATE`, `REJECTED_SERVICE`, `REJECTED_PLAYER`, `LIMIT_REACHED`, `COMPUTED`, `QUEUED`, `ACTION_DONE`, `ACTION_FAILED`, `ACTION_UNCERTAIN`, `GRANTED`, `SKIPPED_OFFLINE`, `DRY_RUN`, `CONFIG_INVALID`.
* **Гарантии.** Один голос награждается один раз (дедуп). Команды и деньги — не более одного раза: если сервер упал посреди выдачи, начатое действие становится `UNCERTAIN` и не повторяется (оно могло как выполниться, так и не выполниться — награду в этом случае проверьте вручную). Не начатые действия той же награды выдаются при следующем входе игрока. Предметы и сообщения — «хотя бы один раз»: при падении между выдачей и записью статуса предмет может выдаться повторно. Дедуп хранится `duplicate-protection.retention-days` дней; повтор голоса старше этого срока будет награждён снова. `dispatchCommand` вернул `true` — это не гарантия эффекта стороннего плагина. Деньги идут через Vault, без него действие `FAILED`.
* **Совместимость.** Голоса CraftRadar (способ «Наш плагин») сторонние плагины наград не видят: награждает только CraftRadar Votes. Голоса других мониторингов через NuVotifier при `handle_votifier_votes: auto` и найденном VotingPlugin/SuperbVote/GAListener/VoteRoulette не награждаются здесь (об этом строка в консоли при старте); `true` при таком плагине — двойные награды, при старте предупреждение.
* **Честно.** Движок проверен автотестами и на реальных серверах (Paper 1.8.8 … 26.1.2, тестовый игрок получает команду, предмет и сообщение; см. матрицу). Vault и сторонние плагины наград на реальном сервере **не проверены**. Первый запуск проверьте через `rewards test <ник> dry`, затем без `dry`.

## Скины CraftRadar (модуль `skins`)

Необязательный модуль: на сервере без лицензии игрок видит свой скин из [библиотеки CraftRadar](https://craftradar.ru/skins.php). **По умолчанию выключен.** Нужен [SkinsRestorer](https://skinsrestorer.net/) 15.x (в `softdepend`); без него модуль спит и пишет об этом в консоль, остальной плагин работает как обычно.

Как работает:

1. Игрок заходит на сервер. Плагин в фоне спрашивает `GET {skins.api_url}/api/v1/skins/player/<ник>` (тайм-аут `timeout_ms`, ответ помнит `cache_minutes`; ошибки сайта — минуту). Главный поток не ждёт.
2. Если у игрока в SkinsRestorer **уже выбран скин** (`/skin <ник>`, `/skin url …`, кастомный скин админа) — ничего не меняется. Модуль трогает только игроков без скина в SR или со своим же скином CraftRadar.
3. Скин ставится через официальное API SkinsRestorer так же, как `/skin url <адрес> [slim]`: подпись текстуры делает MineSkin силами самого SkinsRestorer (его настройки и ключ), результат SR хранит по адресу текстуры. В адресе — sha256 файла, поэтому повторные входы MineSkin не вызывают.
4. Игрок снял скин на сайте или отвязал ник — при следующем входе скин CraftRadar снимается, SR возвращает свой скин по умолчанию.

Подмена чужого скина: сайт отдаёт скин только по нику, который игрок подтвердил в CraftRadar Launcher (вошёл в аккаунт и запустил игру этим ником). Один ник — один аккаунт CraftRadar без учёта регистра; ник из профиля сайта сюда не попадает. Ники вне `^[A-Za-z0-9_]{3,16}$` (например, с префиксом Bedrock) не запрашиваются.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `skins.enabled` | `false` | Включить модуль |
| `skins.api_url` | `https://craftradar.ru` | Адрес сайта ровно как есть (без `www` и хвоста): скин принимается, только если его адрес начинается с этого же адреса. `http://` — только вместе с `allow_insecure_http: true` |
| `skins.timeout_ms` | `3000` | Тайм-аут запроса к сайту, 500–10000 |
| `skins.cache_minutes` | `10` | Сколько помнить ответ по нику, 1–1440 |

Включить: `skins.enabled: true` → `/crvotes reload` (SkinsRestorer должен быть установлен до запуска сервера). Состояние — первая строка `/crvotes status` (`включены`, `спят: SkinsRestorer не установлен`, `спят: API SkinsRestorer 15.x недоступно`). SkinsRestorer 14 и старше не поддерживается. В режиме прокси (SkinsRestorer на BungeeCord/Velocity) API на бэкенде доступно, только если так настроен сам SkinsRestorer — иначе модуль спит. Подробности по ходу работы — при `log_level: debug`. Плащи SkinsRestorer не ставит — `cape_url` модуль не использует.

## Диагностика подключения

Способ «Наш плагин»: кнопка «Проверить подключение» в кабинете проверяет, что плагин опрашивает CraftRadar, и ставит проверочный запрос; плагин забирает его при следующем опросе и подтверждает `diagnostic_ack`. Это не голос: ни события, ни наград.

Способ «Без нашего плагина» (Votifier): кнопка шлёт тестовый пакет (`service` = `CraftRadarDiagnostic` или `additionalData` = `crdg1:<16 hex>`). Если плагин стоит рядом с NuVotifier, он:

- не выдаёт за него награды и не пересылает как голос; в консоль пишет одну строку `Диагностика CraftRadar: получена проверка, награды не выдаются`;
- если в маркере есть id, кладёт в ту же очередь на диске подтверждение `diagnostic_ack` (ключ `diag:<id>`, тот же подписанный канал); сайт отвечает 200 (подтверждено), 404/409/410 (неизвестно/повтор/просрочено) — тогда запись уходит в `rejected/` без повторов; при сетевых ошибках действует обычный backoff;
- если мост выключен или не настроен, награды всё равно не выдаются, в консоль пишется предупреждение `мост не настроен, подтверждение не отправлено`.

## Надёжность

* Каждый голос сначала записывается файлом в `queue/`, поэтому переживает перезапуск сервера и недоступность CraftRadar.
* Повторы сети/5xx: 5 с, 10 с, 20 с, … с разбросом ±20%, потолок 15 минут. Для HTTP 429 учитывается `retry_after`, причём пауза действует на всю очередь.
* HTTP 401/403/404 могут быть временными (сдвиг часов сервера, мост выключен в кабинете, сервер на модерации, деплой, WAF), поэтому событие остаётся в очереди и повторяется с долгой паузой: 5 мин, ×2, потолок 1 час. Предупреждение в консоль — не чаще раза в 10 минут на код, с ответом сервера (секрет не выводится).
* Событие, пролежавшее в очереди больше 7 дней, переносится в `rejected/` с причиной `expired`.
* Редирект (3xx) считается ошибкой конфигурации: укажите в `api_url` точный `https://` адрес. Редиректы плагин не выполняет. Тот же долгий повтор действует при внутренней ошибке отправки (`config_error` в `/crvotes status`).
* Тело запроса не меняется между попытками, заголовок `X-CR-Timestamp` и подпись пересчитываются. Сервер распознаёт повтор как дубликат (HTTP 200), награда не удваивается.
* Одинаковые события `(service, username, timestamp)` в очереди не дублируются.
* Окончательно отклонённые события (400/409, `expired`) лежат в `rejected/` в том же формате, что и очередь, плюс поля `reason`, `http`, `response`. В `rejected/` хранится не больше 1000 файлов (самые старые удаляются). После исправления причины выполните `/crvotes requeue` (все) или `/crvotes requeue <id>` — файлы вернутся в очередь, счётчик попыток обнуляется.
* Отправка идёт в фоне, до 4 запросов одновременно: один зависший запрос не задерживает свежие голоса.
* Состояние очереди (id, время следующей попытки) держится в памяти и читается с диска один раз при старте; главный поток делает только проверку размера в памяти и запись одного маленького файла (с fsync). При старте удаляются недописанные `*.tmp`.

## Как проверить

1. В консоли при старте: `Готово: ключ crk_…, сайт https://craftradar.ru, голоса CraftRadar забираются каждые 5 с.` и `NuVotifier не установлен — это нормально…` (или `NuVotifier найден…`).
2. `/crvotes status`: «Способ в кабинете: «Наш плагин»», «Связь с CraftRadar: последний опрос N с назад».
3. В кабинете «Проверить подключение» — все уровни A–D зелёные. Награду проверьте `/crvotes rewards test <ник> dry`.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| `NuVotifier не установлен — это нормально` | Не ошибка: голоса CraftRadar плагин забирает сам. NuVotifier нужен только для голосов других мониторингов |
| `Способ в кабинете: «Без нашего плагина»` | В кабинете выбран Votifier: голоса CraftRadar придут через NuVotifier, а не опросом. Для работы без NuVotifier выберите «Наш плагин» |
| `ключ не принят (HTTP 401)` в `/crvotes status` | Неверные `key_id`/`secret`, выключен приём от плагина в кабинете или расходится время сервера (NTP) |
| `на CraftRadar ещё не включён режим «Наш плагин»` | Сайт обновляется; пока выберите в кабинете способ «Без нашего плагина» |
| `key_id пуст` / `secret пуст` | Заполните `config.yml`, `/crvotes reload` |
| HTTP 401 / 403 | Неверные `key_id`/`secret`, мост выключен, IP не в списке разрешённых, WAF или сильно расходится время сервера (проверьте NTP). Событие остаётся в очереди и повторяется до 7 дней: исправьте причину, затем `/crvotes flush` |
| HTTP 404 | Сервер удалён, неактивен или на модерации; повтор раз в 5 мин ... 1 ч до 7 дней |
| HTTP 3xx / `config_error` | Проверьте `api_url`: нужен прямой `https://` адрес |
| HTTP 409 / 400 | Мониторинг не зарегистрирован, подтверждение не найдено или неверное поле: подробности в кабинете; событие в `rejected/`, после исправления `/crvotes requeue` |
| Очередь растёт, ошибка «сеть» | Нет доступа к craftradar.ru с хоста (файрвол/DNS) |

## Сборка

Нужен только JDK 21 (Gradle скачивает Wrapper сам, версия и SHA-256 зафиксированы в `gradle/wrapper/gradle-wrapper.properties`):

```
./gradlew build        # тесты + bukkit/build/libs/craftradar-votes-<версия>.jar + SHA256SUMS
```

Модули: `core/` — голоса, очередь, HMAC-транспорт, награды (Java 8 bytecode, без Bukkit); `bukkit/` — клей Bukkit/Votifier, компилируется против spigot-api 1.8.8 и NuVotifier 2.7.1, собирает итоговый jar (gson 2.10.1 затенён в `ru.craftradar.votes.lib.gson`, лицензия — `META-INF/gson-LICENSE.txt`). Сборка воспроизводимая: тот же коммит даёт тот же SHA-256. Подробно: [docs/compatibility/](docs/compatibility/), реальные серверы — `realserver/` (см. [adding-minecraft-version.md](docs/compatibility/adding-minecraft-version.md)).
